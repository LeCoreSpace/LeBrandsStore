3. WHAT TO INJECT ON EVERY STOREFRONT PAGE
━━━━━━━━━━━━━━━━━━━━━━━━
In the theme layout <head>, server-rendered per store, only if the value exists and the integration is enabled:
- Verification meta tags (Meta and Google)
- Meta Pixel base code: fbq('init', PIXEL_ID); fbq('track','PageView')
- One gtag.js loader: gtag('config', GA4_ID); and if set, gtag('config', AW_ID)
Load scripts async. If nothing is enabled, inject no tracking scripts at all (stores must stay lightweight).

Create ONE helper track(eventName, data) that sends each event to both Meta and Google. Theme components call only this helper, never fbq/gtag directly.

━━━━━━━━━━━━━━━━━━━━━━━━
4. EVENTS — WHICH PAGE / ACTION
━━━━━━━━━━━━━━━━━━━━━━━━
| Page / action | Trigger | Meta | Google |
| All pages | page load | PageView | page_view (automatic) |
| Product page | page load | ViewContent | view_item |
| Add to cart button (product page, quick-add on collection/home, upsell sections) | AFTER cart API returns success, not on raw click | AddToCart | add_to_cart (+ Ads conversion if add-to-cart label set) |
| Checkout page | page load | InitiateCheckout | begin_checkout (+ Ads conversion if label set) |
| Place order button | on click — DO NOT fire Purchase here | AddPaymentInfo (optional) | add_payment_info (optional) |
| Order confirmation / thank-you page | page load, only after Razorpay payment verified or COD order created | Purchase | purchase (+ Ads conversion with purchase label if set) |
| Search results (if search exists) | page load | Search | search |

Parameters:
- Meta: content_ids (product/variant id), content_type 'product', contents [{id, quantity}], value, currency 'INR', num_items.
- Google: items [{item_id, item_name, price, quantity, item_category}], value, currency 'INR'.
- Purchase also includes: transaction_id = order number (Google), eventID = orders.tracking_event_id (Meta).
- Use the same product ID everywhere (events and any product feed).

Purchase rules:
- Fire once per order: set browser_purchase_fired_at; skip on refresh or revisit of the thank-you page.
- Failed or cancelled Razorpay payment = no Purchase event.
- If enhanced conversions is ON: call gtag('set','user_data',{email, phone_number}) on the thank-you page before the purchase event.

━━━━━━━━━━━━━━━━━━━━━━━━
5. SERVER-SIDE PURCHASE (only if Meta access token is saved)
━━━━━━━━━━━━━━━━━━━━━━━━
- At checkout, read the _fbp and _fbc cookies (build fbc from the fbclid URL param if missing); save them with IP and user agent on the order.
- When the order is confirmed (Razorpay payment.captured webhook, or COD order creation), POST a Purchase event to the Meta Conversions API (Graph API /{pixel_id}/events):
  - same event_id as the browser event (so Meta deduplicates)
  - action_source 'website', event_source_url
  - user_data: SHA-256 hashed lowercase email and phone (with 91 country code, no +), plus fbp, fbc, IP, user agent
  - same custom_data as the browser event
  - test_event_code if set
- Retry on failure; set meta_capi_sent_at on success.
- If no token is saved, skip this step entirely.

6. ACCEPTANCE TESTS
━━━━━━━━━━━━━━━━━━━━━━━━
- Meta Pixel Helper shows PageView, ViewContent, AddToCart, InitiateCheckout, Purchase with correct INR values.
- With a token + test code: Events Manager → Test events shows Purchase from Browser and Server, deduplicated.
- GA4 DebugView shows the full funnel; Tag Assistant shows the Ads conversion when an AW ID + label are set.
- Refreshing the thank-you page does not refire Purchase.
- A cancelled Razorpay payment fires no Purchase.
- A store with no integrations loads zero tracking scripts.
