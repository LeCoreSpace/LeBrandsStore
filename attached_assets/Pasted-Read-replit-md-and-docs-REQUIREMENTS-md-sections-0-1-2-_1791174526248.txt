B. ACCOUNTS at app.lebrands.store
Database — new migration db/migrations/0003_accounts.sql (don't edit 0001/0002):
- users: email (unique, lowercased), name, phone (optional), password_hash,
  password_algo, created_at, last_login_at, must_change_password (bool).
- sessions: user_id, token_hash (SHA-256 only), expires_at (30 days),
  last_seen_at, user_agent, revoked_at.
- login_attempts: email, ip_hash, success, created_at.
- lebrands_app gets NO direct access to these tables. Use SECURITY DEFINER
  functions (safe search_path, EXECUTE to lebrands_app): register_user,
  get_password_record(email), record_login_attempt, is_login_locked(email, ip_hash)
  (lock after 10 failures in 15 minutes), create_session, get_session(token_hash)
  (returns user + their stores via store_members), revoke_session,
  change_password, check_subdomain, create_brand_and_store(user_id, brand_name,
  subdomain) → creates brand, DRAFT store, store_members row role 'owner'.
Passwords:
- PBKDF2-SHA256 via WebCrypto, 600,000 iterations, 16-byte random salt;
  store algorithm, iterations, salt and hash so it can be upgraded later.
- Minimum 10 characters; reject very common passwords (small built-in list).
- Constant-time comparison. Generic error "Email or password is incorrect".
Pages (server-rendered, same look as homepage):
- /signup (name, email, password, confirm, accept terms checkbox)
- /login, /logout
- / dashboard: the user's stores, or "Create your store" if none
- /stores/new: brand name + store address with live availability check
  (JSON endpoint /api/subdomain-check?name=)
- /account: change password
- /forgot-password: message "Contact support@lebrands.store to reset your
  password" (email reset comes later)
Security: session cookie "__Host-lbs_session" (Secure, HttpOnly, SameSite=Lax,
Path=/, 30 days); reject POSTs whose Origin isn't https://app.lebrands.store;
escape all output; validate all input; never reveal whether an email exists.
Admin script: db/admin-reset-password.js (uses SUPABASE_DB_URL) that sets a
random temporary password for an email, prints it once, and sets
must_change_password = true; user is forced to /account on next login.
