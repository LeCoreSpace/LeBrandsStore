## What we are building
Replace the current 4-step setup (Brand basics, Theme, Products, Review and publish) with one interactive builder, in the style of Shopify Sidekick. The brand never types except for: store name, product prices, stock counts, and uploading photos. Every other answer is a tap on a card, chip, swatch or toggle.

Layout (desktop): left column 420px is a conversation. Ann (our assistant) asks one question at a time, and the answer options appear as cards or chips under the question. Right side is a live preview of the store in our Aura theme, updating after every answer. A thin progress bar on top shows the 14 stages. Every past answer stays visible in the conversation and has an "Change" link that reopens that question.
Mobile: conversation full screen, a floating "Preview" button opens the preview as a bottom sheet.

Route: `app.lebrands.store/stores/:storeId/build`. The old setup routes redirect here. A store that already finished setup opens the normal dashboard, not the builder.

## Product types, HSN and GST
A subcategory (e.g. "Womens Clothing") is too broad for an HSN code. So we add one more level: **product types** (T-shirt, Kurta, Saree (silk), Gold jewellery, Smartwatch...). Each product type carries its HSN code and GST rule, and maps to one or more taxonomy subcategories. This is our app's product list.

Global reference tables (no store_id, SELECT only for lebrands_app, written only by migration/seed):
- `hsn_codes`: code (4 to 8 digits, primary key), description, chapter.
- `tx_product_types`: id, type_key (unique), name, hsn_code (FK hsn_codes), gst_rule ('flat' or 'price_threshold'), rate_low, rate_high, price_threshold (₹, nullable), reviewed_by_ca boolean, note, active boolean.
  Allowed rates: 0, 0.25, 3, 5, 18, 40. CHECK constraint.
- `tx_product_type_subcategories`: product_type_id, subcategory_id, popular_rank (1 to 5 or null), unique (subcategory_id, popular_rank) where not null. Many to many: a Kurta sits under Mens Clothing, Ethnic Wear and Kurtas & Kurtis, and its popularity differs in each.
- `hsn_codes.group_label`: short display heading used to group the "More product types" list (e.g. 6109 "Knitted tops", 4202 "Bags and wallets", 7113 "Precious metal jewellery").

Brands pick product types per collection in stage 6 (top 5 as chips, the rest in a grouped searchable list). Each product then picks one of those types in stage 7, and the type sets HSN and GST automatically:
- flat: gst_rate = rate_low
- price_threshold: gst_rate = rate_low if the per piece selling price (per variant) is at or below price_threshold, else rate_high. Recalculate when the price changes and show the new rate before saving. Variants of one product can have different rates; invoices already handle per line rates.
Store on the product: product_type_id, hsn_code, and on each variant: gst_rate. Store hsn_confirmed_at when the brand taps "Confirm".
If a subcategory has no product types yet, show "Other (subcategory name)" with the chapter level HSN from the seed and a dashboard note "Rate pending CA review". Never blank, never 0% or Exempt unless the type says so.
Rows with reviewed_by_ca = false work normally but show a small "Rate pending CA review" note in the dashboard only (never on the storefront or invoice).
Later changes to a product type never silently change existing products: show "GST rate updated, review" on affected products instead.

Seed (I will provide both files, in batches by category):
- `db/seed/product_types.csv`: type_key, name, hsn_code, gst_rule, rate_low, rate_high, price_threshold, reviewed_by_ca, note
- `db/seed/product_type_subcategories.csv`: subcategory_id, type_key, popular_rank
`hsn_codes` rows are created from the distinct codes in product_types.csv; add group labels in `db/seed/hsn_groups.csv` (hsn_code, group_label), and fall back to the code's chapter name if a label is missing. The import is idempotent (upsert by type_key) so later batches add to it. It fails loudly on an unknown subcategory id or type_key, a rate outside the allowed set, a price_threshold rule without a threshold, or two types with the same popular_rank in one subcategory. Do not invent HSN codes or rates yourself; only import what is in the file.
